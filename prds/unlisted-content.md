# Unlisted posts and pages

Created: 2026-08-16 08:35 UTC
Last Updated: 2026-08-16 08:50 UTC
Status: Complete

## Problem

Content marked `unlisted: true` should be live at its direct URL but invisible everywhere else, including Google. Posts already have partial support (hidden from listings, feeds, sitemap, search) but three things are missing:

1. No `noindex` signal, so Google can still index unlisted URLs if they get linked anywhere
2. Pages have no `unlisted` support at all (no schema field, no sync, no query filters)
3. No admin-visible list of unlisted URLs, and the dashboard `listAll` queries omit `unlisted` so the editor checkbox never hydrates

Smaller leaks: `getDocsPosts`/`getDocsPages` show unlisted docs content in the docs sidebar, and the static `public/raw/index.md` generated by sync lists unlisted posts.

## Proposed solution

Finish the `unlisted` feature end to end:

- Return `unlisted` from `getPostBySlug` and `getPageBySlug`; set `<meta name="robots" content="noindex, nofollow">` in `src/pages/Post.tsx` when rendering unlisted content, restoring `index, follow` otherwise
- Add `X-Robots-Tag: noindex` header on `/api/post` and `/raw/{slug}.md` HTTP responses when the post is unlisted (expose `unlisted` from `getPostBySlugWithContent`)
- Add `unlisted` to the `pages` schema, sync script (`PageFrontmatter`, `ParsedPage`, `parsePageFile`), `syncPagesPublic`, and CMS validators/mutations/exports
- Filter unlisted pages from `getAllPages`, `getFeaturedPages`, `getAllPagesInternal` (sitemap), full text search, semantic search doc fetch, and VFS listings/index/grep
- Skip unlisted in `getDocsPosts`, `getDocsPages`, `getDocsLandingPost`, `getDocsLandingPage`
- Dashboard: include `unlisted` in `listAll` returns for posts and pages, add an Unlisted filter tab and badge to both list views, add the Unlisted checkbox to the pages editor, show a copy-URL action for unlisted rows
- Sync script: exclude unlisted posts and pages from `public/raw/index.md` listing (individual raw files stay accessible by direct URL, which is the point of unlisted)

## Edge cases

- Unlisted plus `published: false`: unpublished wins, nothing is served
- Robots meta must reset to `index, follow` when navigating from an unlisted post to a listed one (SPA navigation, no full page load)
- Existing static `public/raw/{slug}.md` files are served by the static catch-all without the noindex header; the Convex `/raw/` route (registered before the catch-all) handles the header, and the raw index no longer links unlisted slugs
- Demo posts already set `unlisted: true`; they gain the noindex meta, which is fine
- VFS `cat` by exact path still serves unlisted content by design (direct access allowed); only listings/grep hide it
